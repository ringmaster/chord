## Project

Chord is a native macOS web browser written in Swift.
It wraps WebKit and gives functionality similar to the Arc browser from The Browser Company.

## Commits

Make a commit after each major change.
A major change is one of these:

- Work that completes a task in `chord/tasks.md`.
- A new feature or a change to an existing feature that a user can see.
- A change to the architecture, the build setup, or `project.yml`.

Run `make build` and `make test` before each commit, and commit only when both pass.
Make each commit one logically complete unit, and name the Brass task in the message when there is one.

## Commands

- `make build`: regenerate the Xcode project from `project.yml`, then build the Debug app into `.build/`.
- `make run`: build, then open the app.
- `make test`: run the `chord_logic` tests with `swift test`.
- `swift test --package-path Packages/chord_logic --filter AddressInputTests/dottedHostLoadsOverHTTPS`: run one test.
- `make logs`: stream the app's log messages (subsystem `net.asymptomatic.Chord`).
- `make clean`: delete build output and the generated Xcode project.

`Chord.xcodeproj` is generated by XcodeGen and is not committed.
Change `project.yml`, never the generated project.

## Architecture

- `App/Sources` is the AppKit application shell. `main.swift` sets the delegate by hand, because there is no nib. `AppDelegate` builds the main menu and owns the browser windows. `BrowserWindowController` holds one `WKWebView` in a window with a transparent title bar and full-size content.
- `Packages/chord_logic` is a local Swift package for logic that does not need AppKit or WebKit. Put testable logic here so `swift test` covers it without launching the app. The app shell has no headless tests.
- Tests use Swift Testing (`import Testing`, `@Test`, `#expect`).
- The layout follows Owen's Tacks project (`~/Projects/tacks`): XcodeGen, a local logic package, and a Makefile.

## Platform constraints

- The minimum system version is macOS 26. It is the first version that has both `WKWebExtensionController` (web extensions) and the Foundation Models framework (the native Apple model).
- Chord is distributed directly as a notarized Developer ID build, outside the Mac App Store. This lets Chord use the private `_WKInspector` API to dock Web Inspector in a pane. Release builds use the hardened runtime.

## Design goals

- The UI has elegant, modern styling. Every surface is intentionally designed. There are no clunky text boxes or generic configuration forms.
- A command palette controls all actions.
- A sliding sidebar shows spaces, favorites, and pinned sites.
- The user can open multiple "little chord" windows. Each one has minimal chrome and shows a single website. A command-line call can open a new little chord window.
- Domain-specific augments add behavior to specific sites. Augments use JavaScript, HTML, and CSS.
- Bookmarks integrate directly with external bookmark services, Karakeep in particular.
- Models can act on the current page, or navigate between pages and act on them. Supported models are open models through an API and the native Apple model.
- The browser keeps a history of visited sites and shows those sites first in search results.
- The browser supports browser extensions, such as 1Password.
- Browser configuration is simple. For example, the default search engine is DuckDuckGo.
- A developer tools pane gives the standard Safari and WebKit Web Inspector.
