## Project

Chord is a native macOS web browser written in Swift.
It wraps WebKit and gives functionality similar to the Arc browser from The Browser Company.

## Commands

- `make build`: regenerate the Xcode project from `project.yml`, then build the Debug app into `.build/`.
- `make run`: build, then open the app.
- `make test`: run the `chord_logic` tests with `swift test`.
- `swift test --package-path Packages/chord_logic --filter AddressInputTests/dottedHostLoadsOverHTTPS`: run one test.
- `make logs`: stream the app's log messages (subsystem `net.asymptomatic.Chord`).
- `open -g .build/Build/Products/Debug/Chord.app --args -ChordSidebarPinned YES`: open the app in the background with the sidebar pinned open, for screenshots. Use `-g` so the app does not take keyboard focus from the user.
- `open -g .build/Build/Products/Debug/Chord.app --args -ChordDatabasePath /tmp/x.sqlite`: run against a separate database file, so testing leaves the real data alone. Add `open -g -a .build/Build/Products/Debug/Chord.app https://example.com` to open tabs in it.
- `--args -ChordExtraWindows 1` opens more Major Chord windows at launch, for screenshots.
- `--args -ChordPaletteQuery git` opens the command palette at launch with that text, for screenshots.
- `--args -ChordShowAirTrafficControl https://example.com` opens Air Traffic Control testing that link, for screenshots.
- `open "chord://minor?url=https%3A%2F%2Fexample.com"`: open a page in a new Minor Chord window from the command line. The URL must be percent-encoded.
- `--args -ChordOvertonesPath /some/folder` reads overtones from another folder, for testing.
- `--args -ChordShowExtensions YES` opens the Extensions window at launch, for screenshots.
- `--args -ChordKarakeepServer http://127.0.0.1:8799 -ChordKarakeepKey KEY` uses a Karakeep server for one launch without saving anything, for testing against a stub.
- `--args -ChordShowDeveloperTools YES` docks Web Inspector two seconds after launch, for screenshots.
- `make clean`: delete build output and the generated Xcode project.

`Chord.xcodeproj` is generated by XcodeGen and is not committed.
Change `project.yml`, never the generated project.

## Architecture

- `App/Sources` is the AppKit application shell. `main.swift` sets the delegate by hand, because there is no nib. `AppDelegate` opens the database, builds the main menu, and owns the main window.
- `Library` is the shared `@Observable` state over `ChordDatabase`: spaces, every space's tabs, rules, and settings. Views read it and call its methods; it writes to the database, then reloads.
- A Major Chord window is a `BrowserWindowController`. All Major Chord windows share one set of tabs. Each window's own space and active tab are in its `WindowState`.
- `TabSessions` creates one `TabSession` (a `WKWebView`) per tab, the first time the tab is shown, and shares it across windows. A web view is in one window at a time; the key window claims it, and a background window shows a card instead. Each profile gets its own `WKWebsiteDataStore(forIdentifier:)`.
- `BrowserWindowController` lays out the page, the sidebar, the drag strip, and the window buttons in code. `keepUpdated` in `Observe.swift` keeps AppKit views in step with `Library`.
- The command palette (`Palette.swift`) is a SwiftUI overlay. `PaletteResults` in `chord_logic` decides its rows; `BrowserWindowController.paletteCommands()` lists the commands that apply now, and `run(_:)` runs them by id.
- Air Traffic Control (`AirTrafficControl.swift`) is its own window. `RuleEngine` in `chord_logic` decides routes; `Library.destination(for:)` and `AppDelegate.route(_:)` apply them to links from other apps and to new tabs from the palette.
- A tab group is a sidebar tab with a `groupMatcher`. Its members have `parentTabID` set and show in `HeaderStrip` above the page, not in the sidebar. `WindowState.openTab(_:)` is the one place new tabs are created, and it puts a matching URL into its group; links from other apps, palette tabs, and windows a site opens all go through it.
- A Minor Chord window (`MinorChordWindowController`) holds one web view with the profile's website data. It is not a tab and is not saved between launches.
- Links clicked inside pages go through `LinkRouting` in `chord_logic`, then `AppDelegate.routeClickedLink`. Only clicked links to another site are routed; redirects, forms, and script navigation load in place. A matching tab group wins over a rule.
- Overtones are folders in `~/Library/Application Support/Chord/Overtones`. A folder named like a domain applies to that domain and its subdomains; any other folder applies where a rule names it. `OvertoneLibrary` and `OvertoneScript` in `chord_logic` read the folders and build the scripts. `OvertoneManager` watches the folder with FSEvents, and `OvertoneBinding` installs a web view's overtones before each main-frame load, in the `ChordOvertones` content world.
- Web extensions: `ExtensionManager` owns one `WKWebExtensionController` that every web view's configuration shares. Installed extensions and their grants are rows in the `webExtension` table and are applied again at launch. `ExtensionAdapters.swift` makes `TabSession` a `WKWebExtensionTab` and both window controllers `WKWebExtensionWindow`s; tab and window events are reported to the controller where they happen. `SafariExtensionScanner` finds Safari web extensions inside apps.
- Bookmarks go through the `BookmarkService` protocol in `chord_logic`; `KarakeepService` implements it over `HTTPTransport`, which tests replace with a stub. The server address is the `karakeepServer` setting; the API key is in the Keychain (`Keychain` in `Bookmarking.swift`). The palette adds bookmark rows after a short typing pause.
- `WebInspector` docks Web Inspector in the page area through the private `_WKInspector` (`show`, `attach`, `close`) and the private `developerExtrasEnabled` preference. Each call checks that the method exists, so a WebKit change degrades to Safari's Develop menu. Do not set the web view's frame in layout code: it follows the page area through autoresizing, and setting it would cover the docked inspector.
- SwiftUI is used inside AppKit containers, for example `SidebarContent` inside the glass sidebar card. Build custom rows and controls; do not use `List`, `Form`, or stock-styled controls.
- `Packages/chord_logic` is a local Swift package for logic that does not need AppKit or WebKit. Put testable logic here so `swift test` covers it without launching the app. The app shell has no headless tests.
- Tests use Swift Testing (`import Testing`, `@Test`, `#expect`).
- Persistence uses GRDB over SQLite. History search uses SQLite FTS5.
- The layout follows Owen's Tacks project (`~/Projects/tacks`): XcodeGen, a local logic package, and a Makefile.

## Platform constraints

- The minimum system version is macOS 26. It is the first version that has both `WKWebExtensionController` (web extensions) and the Foundation Models framework (the native Apple model).
- Chord is distributed directly as a notarized Developer ID build, outside the Mac App Store. This lets Chord use the private `_WKInspector` API to dock Web Inspector in a pane. Release builds use the hardened runtime.

## Design goals

- The UI has elegant, modern styling. Every surface is intentionally designed. There are no clunky text boxes or generic configuration forms.
- A command palette controls all actions.
- A sliding sidebar shows spaces, favorites, and pinned sites.
- The user can open multiple Major Chord windows with File > New Window. They share one set of tabs.
- The user can open multiple Minor Chord windows. Each one has minimal chrome and shows a single website. A command-line call can open a new Minor Chord window.
- Chord is the default handler for `http` and `https` URLs. Air Traffic Control decides whether an opened URL goes to a new Minor Chord window or to a sidebar tab in the main Chord window.
- Air Traffic Control is the UI for match rules. A rule matches URLs, for example by domain, and triggers actions: overtones, tab grouping, profile routing, and window routing. Its UX is custom and polished. Do not use stock SwiftUI forms or controls for it.
- A sidebar tab can group tabs by domain. New tabs that match its rule open as header tabs across the top of the content area, not in the sidebar. Clicking the sidebar tab shows that pane with its header tabs.
- History has no pane of its own. The command palette searches it.
- The window always has a surface to drag it by. The window buttons (close, minimize, zoom) appear only in the sidebar flyout, never over page content.
- Domain-specific overtones add behavior to specific sites. Overtones use JavaScript, HTML, and CSS.
- Bookmarks integrate directly with external bookmark services, Karakeep in particular.
- Models can act on the current page, or navigate between pages and act on them. Supported models are open models through an API and the native Apple model.
- The browser keeps a history of visited sites and shows those sites first in search results.
- The browser supports browser extensions, such as 1Password.
- Browser configuration is simple. For example, the default search engine is DuckDuckGo.
- A developer tools pane gives the standard Safari and WebKit Web Inspector.
